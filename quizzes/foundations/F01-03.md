# F01-03 — Stateless workers, retry and circuit breakers

5 soru. Soruların her birinde kaç seçenek seçileceği belirtilmiştir.

## 1. Where should a scalable Cloud Run worker persist application data in the module's example?

**Select one.**

- A. The container's local filesystem as the only durable copy
- B. Shared mutable process state held by another worker
- C. A separate database such as Firestore
- D. Worker-local memory replicated manually to every new instance

## 2. Which two lifecycle properties help stateless workers scale reliably?

**Select two.**

- A. Keep durable application state only in instance memory
- B. Shut down gracefully on a termination signal
- C. Delay startup until every other worker has started
- D. Start quickly

## 3. Which response is recommended for transient network failures?

**Select one.**

- A. Retry indefinitely without a final failure path
- B. Retry with exponential backoff
- C. Apply a circuit breaker permanently after the first transient failure
- D. Retry continuously with a constant zero delay

## 4. A downstream service has a long-lasting outage. What mechanism prevents wasted retries and CPU cycles?

**Select one.**

- A. Increase worker count to generate more retries
- B. Keep a synchronous request open until the service recovers
- C. Retry with shorter intervals after every failure
- D. A circuit breaker

## 5. The recommendation engine is unavailable. Which user-facing response illustrates graceful degradation?

**Select one.**

- A. Return a fatal error for the whole page
- B. Require users to reload until the engine recovers
- C. Hide the recommendation section temporarily
- D. Retry indefinitely before rendering any other content
