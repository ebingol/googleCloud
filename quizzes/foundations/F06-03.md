# F06-03 — Containers, build steps and shared workspace

5 soru. Soruların her birinde kaç seçenek seçileceği belirtilmiştir.

## 1. Why can containers start faster and use fewer resources than traditional VMs in this explanation?

**Select one.**

- A. Each container boots a separate full guest OS
- B. Containers never need libraries or a runtime
- C. They share the host kernel instead of each running a complete guest OS
- D. Every container requires a dedicated hypervisor

## 2. Which two benefits are explicitly attributed to containers?

**Select two.**

- A. Separation of development and operations responsibilities
- B. A requirement to rebuild a different image for every environment
- C. Guaranteed immunity from vulnerabilities
- D. Workload portability

## 3. What executes each Cloud Build build step in the module?

**Select one.**

- A. Only a shell process with no container isolation
- B. Only a Kubernetes Deployment created manually
- C. A Docker container
- D. A mandatory dedicated VM that persists between all builds

## 4. Which directory persists build-step outputs for subsequent steps within the same build?

**Select one.**

- A. /tmp in an unshared step filesystem
- B. /workspace
- C. /boot in the container image
- D. /home in every unrelated build VM

## 5. Which two configuration or integration facts match the module?

**Select two.**

- A. Every step must build a new container image
- B. Build status notifications can be published to Pub/Sub
- C. Only XML is accepted for build configuration
- D. Build configuration can be YAML or JSON
