# O01-03 — Development, technology choice and independent scaling

5 soru. Her soruda seçilecek cevap sayısı belirtilmiştir.

**Kaynak türü:** Introduction to Microservices PDF.

## 1. Which two advantages are linked to a smaller microservice codebase?

**Select two.**

- A. Easier unit testing with clear boundaries
- B. A guarantee that interface changes cannot affect callers
- C. Automatic elimination of distributed integration testing
- D. Easier understanding and updates

## 2. When can updating one service affect other services despite independent deployment?

**Select one.**

- A. When a breaking change is made to its interface
- B. Only when all services use the same database engine
- C. Whenever its internal variable names change without interface changes
- D. Whenever internal code is refactored while preserving API behavior

## 3. Why can services use different programming languages and frameworks?

**Select one.**

- A. All services share the same language runtime in one process
- B. The ESB requires identical technology stacks
- C. Callers depend on API interfaces rather than internal implementation technology
- D. Every caller must compile the callee's source code

## 4. A Java orders service calls a Python product service hosted on another platform. Which principle permits this?

**Select one.**

- A. The caller must be rewritten in Python first
- B. The two services must share one database driver
- C. Both services must run in the same process
- D. API-based communication across platform boundaries

## 5. Only the orders service experiences a traffic spike. What scaling approach matches the module?

**Select one.**

- A. Add capacity to orders independently and reduce it as traffic falls
- B. Always merge orders and reviews into one deployment
- C. Scale every service to the orders peak permanently
- D. Keep every service at a fixed maximum allocation
